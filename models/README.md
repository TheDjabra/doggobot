# Models

Binary weights are **not** in git. This directory holds the metadata that describes them and the
instructions to rebuild the rest.

| File | In git? | What it is |
|---|---|---|
| `person-yolo11n.json` | yes | Luxonis export metadata: 416x416, 1 class (`person`), tensor names and thresholds. The record of what the model actually is. |
| `person-yolo11n_openvino_2022.1_5shave.blob` | no | Compiled network. **5 shaves, not 6**: with StereoDepth, ImageManip, SpatialLocationCalculator and ObjectTracker in the pipeline only 5 SHAVE cores remain, and a 6-shave blob refuses to start. |
| `person-yolo11n-416.tar.xz` | no | NN Archive, generated by `tools/make_nn_archive.py`. Build output. |
| `vosk-small-en/` | no | Speech model, 68 MB. `bash tools/get_vosk_model.sh` fetches it. |

## Rebuilding

The detector was trained separately (YOLO-World auto-labels over COCO val2017, YOLO11n).
Starting from the OpenVINO IR (`.xml` + `.bin`) that tools.luxonis.com produces:

```bash
# 5-shave blob, from the IR
python3 -c "import blobconverter; print(blobconverter.from_openvino(
    xml='person-yolo11n.xml', bin='person-yolo11n.bin',
    data_type='FP16', shaves=5, version='2022.1', use_cache=False))"

# NN Archive around it, for DepthAI v3
docker exec Doggobot python3 .../tools/make_nn_archive.py
```

The archive's decoding `subtype` must be **`yolov6r2`**, which is the Luxonis *export format* and
not the model's architecture generation. `yolov6` yields garbage boxes at high confidence and
`yolov8` yields low confidence. Detail in `docs/hardware.md` and the build log.
